FLOODGUARD BD — GLOFAS-ONLY DEPLOYMENT

Build command:
pip install -r requirements.txt

Start command:
gunicorn --workers 1 --threads 4 --timeout 180 --bind 0.0.0.0:$PORT app:app

DATA SOURCE
-----------
Copernicus CEMS / GloFAS via EWDS API:
https://ewds.climate.copernicus.eu/api
Dataset: cems-glofas-forecast
Variable: river_discharge_in_the_last_24_hours
Operational hydrological model: LISFLOOD

AUTHENTIC-DATA GUARANTEE
------------------------
The production hydrological path contains NO synthetic fallback and NO BWDB dependency.
The server automatically tries the newest available operational GloFAS issue date and can step back several days if the newest daily issue is not yet published.
A successful real snapshot is persisted locally and reused after a process restart. If no real snapshot has ever been fetched, the UI stays in a connecting state rather than inventing hydrological values.

SCIENTIFIC DEFINITION
---------------------
GloFAS supplies forecast river discharge (m³/s), not Bangladesh gauge water level.
FloodGuard's public signal is a transparent percentile score within each zone's loaded 15-day GloFAS forecast window. It is NOT an official Bangladesh flood-warning threshold.
Research Mode exposes P10/P50/P90 ensemble evidence, operational replay, and modelled-target verification.

RENDER NOTE
-----------
The service intentionally uses one Gunicorn worker because the in-process GloFAS refresh and alert loop need one owner. Render Free web services have an ephemeral filesystem, so the local real-data cache and SQLite account database are not permanent across redeploy/spin-down.
For permanent accounts/alert history, connect the app to a persistent Postgres database later.
