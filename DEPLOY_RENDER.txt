FLOODGUARD BD — GLOFAS-ONLY / RENDER FREE

BUILD
-----
pip install -r requirements.txt

START
-----
gunicorn --workers 1 --threads 1 --timeout 120 --bind 0.0.0.0:$PORT app:app

REQUIRED ENVIRONMENT
--------------------
SECRET_KEY=<long random value>
CDS_API_KEY=<your Copernicus EWDS/CDS API key>

OPTIONAL
--------
GEMINI_API_KEY=<optional; grounded local Copilot fallback exists>
EMAIL_SCRIPT_URL=<recommended HTTP email webhook for Render Free>
VAPID_PUBLIC_KEY=<optional browser push>
VAPID_PRIVATE_KEY=<optional browser push>
VAPID_CLAIMS_EMAIL=<mailto: address used for VAPID claims>
ENABLE_BACKGROUND_ALERTS=false
GLOFAS_CACHE_SECONDS=1800
GLOFAS_ISSUE_LOOKBACK_DAYS=3
GLOFAS_FORECAST_DAYS=15

DATA SOURCE
-----------
Copernicus CEMS / GloFAS via EWDS API: https://ewds.climate.copernicus.eu/api
Forecast dataset: cems-glofas-forecast
Forecast variable: river_discharge_in_the_last_24_hours
Operational hydrological model: LISFLOOD / GloFAS v4.0

AUTHENTIC-DATA GUARANTEE
------------------------
The hydrological runtime path has NO synthetic fallback and NO BWDB dependency. If EWDS data cannot be fetched, the UI stays unavailable/stale rather than inventing values.

MONITORING
----------
Six target regions are used to reduce EWDS payload size on Render Free while keeping representative geographic coverage: Sylhet, Kurigram, Sirajganj, Rajshahi, Faridpur and Feni. These are GloFAS target locations, not gauge stations.

SCIENTIFIC DEFINITION
---------------------
GloFAS supplies forecast river discharge (m³/s), not Bangladesh gauge water level. The public signal is a percentile position inside each zone's 15-day forecast window, not a flood probability or official warning threshold.

RESEARCH / VERIFICATION
------------------------
Research ensemble is selected-zone and on-demand. Historical verification uses the operational GloFAS historical V4 product and compares it with an operational forecast replay. This is model-vs-model verification, not independent gauge truth.

----------------
